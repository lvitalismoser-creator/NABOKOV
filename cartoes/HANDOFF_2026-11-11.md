### Como a exportação funciona

```
peças da ordem → buildDoc() → { title, blocks } → render(doc, formato) → bytes
                                              └→ toHTML() → pré-visualização e PDF
```

- Bloco: `title`, `lead` (nota geral da ordem), `h` (cabeçalho de ficha), `p` (com `runs: [{ text, b, i }]`), `sep` (`* * *`), `note`.
- Formato novo = uma entrada em `FORMATS` + um ramo em `render`.
- PDF: o documento vai para `#print-root`; o CSS de impressão esconde o resto. Desktop: `printToPDF`. Navegador: `window.print()`.

## 6. Armadilhas técnicas desta sessão

- **`npm test` puro não passa em contêiner Linux**, por três motivos do ambiente:
  1. Sem tela: use `xvfb-run -a`.
  2. Como root, o Electron só abre sem sandbox: `ELECTRON_DISABLE_SANDBOX=1` (o Playwright já passa `--no-sandbox`, mas o teste da segunda instância lança o Electron direto).
  3. O Playwright do `package-lock` (1.64.1) pede o Chromium 1248 e o contêiner tinha o 1243: fiz um symlink em `/opt/pw-browsers`, fora do repositório. Não rode `playwright install`.
- **`TextDecoder` remove o BOM por padrão.** Para conferir o BOM do `.txt`, use `{ ignoreBOM: true }`.
- **O primeiro instantâneo de um perfil novo é o do cartão em branco** (ele é feito na primeira gravação). Em teste, grave o `projeto.json` antes de abrir o app para ter um instantâneo com conteúdo.
- **Diálogo nativo no Electron não se clica.** Nos testes: `app.evaluate(({ dialog }, p) => { dialog.showSaveDialog = async () => ({ canceled: false, filePath: p }) }, caminho)`.
- **Texto de PDF do Chromium não é legível direto** (fluxos comprimidos, glifos numerados). Use `pdfText()` de `tests/helpers.cjs` e compare sem espaços.
- **Qualquer elemento novo direto no `<body>` some na impressão** (`body > * { display: none }` em `@media print`). É de propósito; só o `#print-root` aparece.
- **`src/export.mjs` e `src/zip.mjs` têm extensão `.mjs`** para os testes `.cjs` poderem carregá-los com `await import()`; o esbuild os empacota normalmente.
- No ODF, espaços repetidos e o espaço inicial do parágrafo somem se não virarem `<text:s/>`.
- No `.docx`, não fixe a fonte para todos os sistemas de escrita (`w:eastAsia`, `w:cs`): o LibreOffice deixou de mostrar caracteres japoneses quando fiz isso.
- Continuam valendo as armadilhas do handoff anterior: não editar `index.html`; no Electron, testes sempre com `CARTOES_DATA_DIR`; esperar `.ProseMirror-focused` antes de digitar; `window.prompt()` não existe no Electron.
