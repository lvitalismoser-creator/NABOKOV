- **Caminho combinado:** o dono gera o instalador na máquina dele, na pasta do clone:

  ```bash
  git pull
  npm install
  npm run dist
  ```

  O resultado é `dist\Cartoes-Setup-1.4.1.exe`.
- **Até onde ele chegou em 13-11:** `git pull` ("Already up to date") e `npm install` (298 pacotes, sem erro). **Não se sabe se o `npm run dist` rodou nem se funcionou.** É a primeira coisa a perguntar.
- **O que apareceu no caminho, na máquina dele:**
  - O PowerShell bloqueava o `npm` ("execução de scripts foi desabilitada"). Ele resolveu com `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. A alternativa sem mudar nada é usar `npm.cmd`.
  - O npm dele é mais novo e **não executou os scripts de instalação** do `esbuild` e do `electron-winstaller` (aviso `install-scripts ... not yet covered by allowScripts`). Se o `npm run dist` falhar com erro do `esbuild`, o próprio aviso indica `npm install-scripts approve esbuild electron-winstaller` seguido de `npm install`. **Esse comando não foi testado.**
  - **O clone dele fica dentro do Dropbox** (`C:\Users\Leonardo\Dropbox\NABOKOV\Git Clone NABOKOV\NABOKOV\cartoes`). A `node_modules` e a `dist` vão ser sincronizadas, e o Dropbox pode segurar arquivos e causar `EPERM`/`EBUSY` no build. Saídas: pausar a sincronização durante o build, ou clonar fora do Dropbox.
- **Alternativa não tentada:** um fluxo do GitHub Actions que monte o instalador num Windows do GitHub e o deixe para download. Foi oferecida; o dono não respondeu.

## 7. Ambiente das sessões em nuvem (Linux)

O que foi preciso montar, porque não fica guardado entre sessões:
